# Telegram-бот

Сервис `tgbot` пересылает сообщения из Telegram в запущенную LLM (qwen или gemma),
а команду `/image` — в запущенный генератор изображений (SDXL или Qwen-Image).
У каждого пользователя свои сессии с отдельной историей. Сессиями управляют из
чата. Настройки задаются через FastAPI: REST API и страница http://127.0.0.1:8084.

Бот работает в режиме long polling: публичный адрес и webhook не нужны, наружу
открыт только исходящий доступ к `api.telegram.org`. Бот не занимает GPU, поэтому
`make qwen`, `make gemma`, `make sdxl`, `make qwen-image` и `make models-stop`
его не останавливают. Он сам находит модель, которая сейчас запущена.

## Подготовка и запуск

1. Создайте бота у [@BotFather](https://t.me/BotFather) (`/newbot`) и сохраните токен.
2. Узнайте свой Telegram id, например у [@userinfobot](https://t.me/userinfobot).
3. Запустите:

```bash
make tgbot-key      # добавляет в .env случайный TGBOT_ADMIN_KEY (для нового .env это делает prepare.sh)
make tgbot-build
make tgbot-test     # тесты без сети и GPU
make tgbot          # http://127.0.0.1:8084
```

4. Откройте http://127.0.0.1:8084 и войдите по `TGBOT_ADMIN_KEY` из `.env`.
   Ключ хранится в `sessionStorage` вкладки.
5. В разделе «Токен бота» вставьте токен и нажмите «Проверить и применить».
   Токен проверяется через `getMe`, после чего polling перезапускается без
   перезапуска контейнера.
6. В «Настройках» укажите свой Telegram id в поле «Администраторы» и сохраните.
7. Запустите модель (`make qwen` или `make gemma`) и отправьте боту `/start`.

Вместо шагов 5–6 можно задать `TGBOT_TOKEN` и `TGBOT_ADMINS` (id через запятую)
в `.env`. Эти значения применяются только к пустой базе, дальше действует то, что
сохранено через страницу или API.

## Доступ

- Администраторы из настроек получают доступ сразу.
- Любой другой пользователь после `/start` получает статус `pending`.
  Администраторам приходит заявка с кнопками «Одобрить» и «Отклонить».
  Одобрить можно также командами `/allow <id>`, `/block <id>`, списком `/users`
  или на странице настроек.
- Бот отвечает только в личных чатах, сообщения из групп игнорируются.
- Бот не проверяет пароли и не предназначен для публичного доступа: в модели
  попадает всё, что пишут одобренные пользователи.

## Команды

| Команда | Действие |
|---|---|
| текст | сообщение в LLM в активной сессии (сессия создается автоматически) |
| `/new [название]` | новая сессия, она становится активной |
| `/sessions` | список сессий с кнопками переключения и удаления |
| `/switch <id>`, `/delete <id>` | переключить или удалить сессию |
| `/rename <название>` | переименовать активную сессию |
| `/clear` | очистить историю активной сессии |
| `/system [текст]` | показать или задать системный промпт сессии; `/system reset` сбрасывает |
| `/model` | какая LLM и какой генератор сейчас доступны |
| `/image <промпт>` | изображение из запущенного SDXL или Qwen-Image |
| `/cancel` | прервать свой текущий запрос |
| `/users`, `/allow <id>`, `/block <id>` | для администраторов |

Ответ LLM появляется постепенно: сообщение редактируется примерно раз в
1.5 с. Пока ответ генерируется, он показывается обычным текстом: незакрытая
разметка сломала бы отправку. Готовый ответ конвертируется из Markdown модели
в Telegram HTML (`tgbot/render.py`, markdown-it-py):

| Markdown | В Telegram |
|---|---|
| `**жирный**`, `*курсив*`, `~~зачеркнутый~~`, `` `код` `` | те же стили |
| заголовки `#` | жирная строка |
| списки, в том числе вложенные | `•` / `1.` с отступом |
| блоки ```` ``` ```` | моноширинный блок с языком |
| таблицы | выровненная таблица в моноширинном блоке |
| `> цитата` | цитата (вложенные сливаются: Telegram их не поддерживает) |
| ссылки http(s) | ссылки, без превью |
| HTML из ответа, картинки, прочее | текстом |

Длинный ответ делится между блоками, чтобы не разрезать разметку. Слишком
длинный блок кода делится по строкам на несколько блоков, прочие слишком
длинные блоки отправляются обычным текстом. Если Telegram все же отклонит
разметку, та же часть уходит обычным текстом, и в логе появляется
предупреждение. В истории сессии хранится исходный Markdown.

Все пользователи работают с одной моделью по очереди: одновременно
выполняется один LLM-запрос и одна генерация изображения. Остальные ждут, и
бот сообщает место в очереди. У каждого пользователя может быть только один
активный запрос. Лимит запросов в минуту на администраторов не действует.
Если прервать запрос через `/cancel`, уже показанная часть ответа остается в
истории с пометкой `[прервано]`.

В LLM отправляются системный промпт и последние сообщения сессии в пределах
«Сообщений истории» и «Символов контекста». Сессии разных пользователей
изолированы: каждый запрос к базе фильтруется по Telegram id владельца.

`/image` определяет генератор по health-проверке (`make sdxl` или
`make qwen-image`). Для Qwen-Image используется workflow запущенного DiT
(`/local-qwen-image/config`), графы монтируются из `qwen-image/workflows`.
Seed случайный и указывается в подписи.

## Настройки и API

Все `/api/*` требуют заголовок `Authorization: Bearer $TGBOT_ADMIN_KEY`.
Порт открыт только на loopback хоста.

```bash
K=$(sed -n 's/^TGBOT_ADMIN_KEY=//p' .env)
curl -H "Authorization: Bearer $K" http://127.0.0.1:8084/api/status
curl -H "Authorization: Bearer $K" -X PUT -H 'Content-Type: application/json' \
  -d '{"token": "123456789:AA..."}' http://127.0.0.1:8084/api/settings/token
curl -H "Authorization: Bearer $K" -X PUT -H 'Content-Type: application/json' \
  -d '{"admins": [123456789], "rate_limit_per_min": 20}' http://127.0.0.1:8084/api/settings
```

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/status` | состояние polling, username бота, доступные модели |
| GET / PUT | `/api/settings` | настройки; в ответе токен всегда замаскирован |
| PUT / DELETE | `/api/settings/token` | проверить и применить токен / отключить бота |
| GET | `/api/users` | пользователи, статусы, число сессий |
| POST | `/api/users/{id}/allow` или `/block` | доступ пользователя |
| GET | `/health/live`, `/health/ready`, `/metrics` | без ключа |

Настраиваются: администраторы, системный промпт по умолчанию, лимиты истории,
длина сообщения, `max_tokens`, temperature, таймаут, запросов в минуту и адреса
backends (`имя=URL`). Из LLM backends выбирается первый ответивший на `/health`.

Backends ограничены сервисами стека: LLM — `qwen`, `gemma`; изображения —
`sdxl`, `qwen-image`, и хост в URL должен совпадать с именем (порт можно
менять). IP-адреса, `host.docker.internal` и другие сервисы отклоняются API
и игнорируются, даже если записаны в базу. Причина: в Docker Desktop любой
контейнер достает до портов, опубликованных на loopback хоста, и до других
bridge-сетей по IP, поэтому только сетевой изоляции недостаточно, чтобы бот
не мог обратиться к `qwen-image-uc`.

## Данные, логи, мониторинг

База SQLite: `outputs/tgbot/bot.db`. В ней токен, пользователи, сессии и
полная история переписки. Файл доступен только владельцу каталога, в резервные
копии добавляйте его осознанно. Чтобы сбросить всё, остановите сервис и удалите
`outputs/tgbot/bot.db*`.

Токен не выводится в логи: фильтр заменяет его на `***`. Тексты сообщений
в логи тоже не пишутся. Логи: `make logs-tgbot` и общий dashboard Grafana (модель
`tgbot`). Метрики Prometheus (job `tgbot`): `tgbot_requests_total{kind,result}`,
`tgbot_request_seconds`, `tgbot_waiting_requests`, `tgbot_polling`. Алерт
`TgbotNotPolling` срабатывает, если сервис запущен без рабочего токена.

`make tgbot-browser-test` проверяет страницу настроек в headless Chromium.
Скриншоты сохраняются в `outputs/tgbot/screenshots`. Для него нужен запущенный `make tgbot`.

## Тесты

`make tgbot-test` запускается в контейнере без сети:
- хранилище и изоляция сессий;
- логика команд, очередь, `/cancel`, лимиты;
- API: ключ, маскировка токена, валидация;
- клиенты LLM и генераторов на поддельных HTTP-ответах;
- конвертер Markdown → Telegram HTML: экранирование, баланс тегов, разбиение;
- сквозной сценарий через настоящий aiogram polling против поддельного
  Telegram Bot API: заявка, одобрение кнопкой, стриминг ответа, сессии,
  `/image`, игнорирование групп, горячая смена токена, отправка HTML и
  запасной вариант обычным текстом.
